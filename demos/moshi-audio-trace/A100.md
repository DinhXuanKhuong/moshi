# Trace original Moshiko on an A100

This run uses Kyutai's original Moshiko BF16 language weights, pretrained Mimi, and the matching SentencePiece tokenizer. The runner downloads about 15.8 GB once and keeps it on the attached volume. It writes a separate directory for each run. [Checkpoint files](https://huggingface.co/kyutai/moshiko-pytorch-bf16/tree/2bfc9ae)

## 1. Publish the tracer from your local checkout

Run these commands from your local Moshi repository. Use a feature branch for the demo.

```bash
git switch -c moshiko-a100-trace
git add scripts/trace_moshi_audio.py scripts/run_moshiko_gpu_trace.sh scripts/build_moshi_explorer.py demos/moshi-audio-trace/
git diff --cached --stat
git commit -m "Trace pretrained Moshiko on CUDA and package the offline explorer"
git push -u origin moshiko-a100-trace
```

## 2. Connect and check the volume

Run this from your local terminal.

```bash
ssh exouser@149.165.159.74
```

On the first connection, compare the host-key fingerprint with the one provided by the instance administrator before accepting it. Enter your instance password at the SSH prompt. The terminal hides password input. If the connection times out, check that the instance accepts SSH on TCP port 22 from your network, or ask the administrator for the intended SSH route.

Run the following after the prompt changes to the remote machine.

```bash
nvidia-smi
findmnt --target /media/volume/RealtimeSpeechLM
df -h /media/volume/RealtimeSpeechLM
```

Check that the listed GPU is an A100 with enough free GPU memory for the BF16 weights and inference state, and that `df` shows the attached volume. Then create a workspace and clone the branch you pushed.

```bash
export MOSHI_WORK=/media/volume/RealtimeSpeechLM/moshiko-trace
mkdir -p "$MOSHI_WORK"
cd "$MOSHI_WORK"
git clone --branch moshiko-a100-trace https://github.com/DinhXuanKhuong/moshi.git
cd moshi
```

## 3. Set up Python and verify CUDA

Use an available Python 3.10–3.13 interpreter with `venv` support. The commands below install PyTorch 2.7.1 with CUDA 11.8, which also works with newer compatible NVIDIA drivers. Use the CUDA 12.6 or 12.8 wheel from the same PyTorch release if your instance administrator specifies that runtime. [PyTorch wheel commands](https://pytorch.org/get-started/previous-versions/#v271)

```bash
python3 -m venv "$MOSHI_WORK/.venv"
source "$MOSHI_WORK/.venv/bin/activate"
export PIP_CACHE_DIR="$MOSHI_WORK/pip-cache"
export HF_HOME="$MOSHI_WORK/huggingface"

python -m pip install 'torch==2.7.1' --index-url https://download.pytorch.org/whl/cu118
python -m pip install ./moshi
python -m pip check
python -c 'import torch; print(torch.__version__, torch.cuda.get_device_name(0)); print(torch.ones(1, device="cuda", dtype=torch.bfloat16))'
```

## 4. Run the pretrained trace

Run this from the cloned repository with the virtual environment active.

```bash
bash scripts/run_moshiko_gpu_trace.sh \
  "$MOSHI_WORK/checkpoints" "$MOSHI_WORK/runs/sample-a100"
```

The default input asks “Hello Moshi. What is two plus two?” The runner uses top-k sampling with seed 0 and adds 100 silence frames (eight seconds) to capture the reply. It prints the emitted text in the terminal. To use your own audio, pass `--input /path/to/input.wav`. To capture a longer reply, pass `--tail-frames 150` and choose a new output directory. Checkpoint assets are reused between runs. Tracing collects tensor statistics and disables CUDA graphs, so its timings include instrumentation overhead.

The output directory contains `trace.json` with per-module shapes and statistics, raw and emitted token IDs, and SentencePiece mappings. It also contains `terminal.txt`, `moshiko-reply.wav`, the input and Mimi reconstructions, and a self-contained `explorer.html`.

## 5. Open the real trace locally

In a **local terminal**, copy the HTML back to your machine.

```bash
scp exouser@149.165.159.74:/media/volume/RealtimeSpeechLM/moshiko-trace/runs/sample-a100/explorer.html ./moshiko-a100.html
```

Open `moshiko-a100.html` in your browser. In **Temporal LM**, the recorded hidden state should read `[1 × 1 × 4096]` and the layer inspector should list 32 layers. In **Depformer**, conditioned depth input should read `[1 × 1 × 1024]`. Select **Moshiko reply** to listen and **Align streams** to inspect which text and audio IDs were emitted together.

To bring back the raw trace, terminal log, and separate WAVs as well, copy the entire run directory. If you later update your local explorer, regenerate the HTML from that directory using the local checkout.

```bash
scp -r exouser@149.165.159.74:/media/volume/RealtimeSpeechLM/moshiko-trace/runs/sample-a100 .
python3 scripts/build_moshi_explorer.py ./sample-a100
```
